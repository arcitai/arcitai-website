# AI Agent Defense Factory

Local source candidate `0.1.0`. Operator: Arc’IT AI within an explicitly authorised customer scope. Purpose: maintain a repeatable, evidence-backed review and remediation process for an AI-enabled system and the code behind it.

Entry: [defense-factory](.agents/skills/defense-factory/SKILL.md). Operating contract: [HANDBOOK.md](HANDBOOK.md).

## Input and output

Input: exact system/repository/revision, security invariants, target authorisation, approved tools/environment and the permitted operation: review, validation, patch or verification. Output: scoped findings/verdict, repeatable evidence, residual gaps and optional reviewed patch candidate. No clean-system certificate or automatic release.

The system can consume a Software Factory change or be invoked separately for an authorised existing setup. Its finding record links back to the originating work ID and immutable commit. Findings are investigated before remediation and verified before deliberate closure.

## Included responsibilities

- Review relevant code and the agent's data/tool/permission boundaries.
- Deduplicate and validate findings with evidence suited to the claim.
- Prepare one authorised, focused fix per accepted finding.
- Check the original failure and legitimate behaviour again.
- Maintain private finding status, evidence gaps and regression cases over time.
- Feed a protected Security overview without granting it remediation or release authority.

Codex Security can supply selected methods; Daybreak is an optional, entitlement-dependent capability, not a product requirement or partner claim. A customer's permitted scope and provider terms must both hold.

## Present capability

The method and handbook are drafted; the dashboard contains example records only. No scan, exploit, customer-data access, model run, remediation job or release gate has been configured or performed. Isolation, identity, tools and exact target authorisation remain activation requirements.
